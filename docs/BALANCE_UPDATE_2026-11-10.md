## 范围与目标

补上前期迎战牌的防御收益、力量的多段输出选择，以及能力部署回合的格挡；调整回收与连续攻击的衔接。仍为 89 张卡、178 个基础与升级牌面，奖励池 83 张。初始卡组仍是打击 × 4、防御 × 4、霆爪、挺身迎战。

「崩山」保留名称；原 C06「进逼」改名为「狂乱挥击」。所有卡牌 ID 保持不变。

## 触发与选择边界

- C06 使用原生随机多段攻击命令，同一张牌保持一个攻击命令边界；每段通过原生战斗目标随机流重新选择敌人，不要求手动选择目标。
- U08 的额外伤害是真正的第二个普通攻击段。两段分别接受力量、攻击强化和普通攻击段响应。第二段使用具名 `DamageVar`，预览也走原生伤害修正。
- U08 以实际出牌开始前的咬痕快照判断追加段。第一段新施加的咬痕不会令本次实际出牌或其效果重演凭空多打一段；原有目标死亡检查继续适用。
- C15 基础版在有合法候选时回收 1 张；升级版可选 0、1 或 2 张。保持既有雷法定义与手牌容量处理。
- R16 在实际出牌的整个结算序列结束时奖励一次属性。多段攻击、效果重演不额外增加奖励次数；技能本身的正数格挡才计入敏捷条件。攻击给挡、能力部署给挡和雷甲的被动格挡不触发敏捷。
- U21 及其配套卡 U27、U34、U38、U40 的实现不变。领域仍按每次实际攻击牌触发一次；U02 仍按普通攻击段触发；雷伤按批次计数，不按敌人数计数。

## 验证边界

本轮同步基础与升级牌面、独立数值契约、已有原生验收场景及其观察结果比较器。原生场景包含随机段数与击杀后重选、C15 升级的 0 / 1 / 2 张回收、U08 首次咬痕与预先咬痕、力量与强化、领域与 U02、R16 的属性归属及实际出牌和重演区别。

Python 比较器的合成数据自测仅验证比较器会接受正确收据、拒绝错误收据；它们不等同于在游戏里完成验收。SDK 独立 fixture 与游戏内验证分别记录。当前环境没有安装游戏程序集与 BaseLib，生产构建及原生游戏场景不能在此执行；未生成或宣称可直接安装的发布包。PR 中记录本轮实际执行的检查结果。

### 本轮实际执行结果

- 使用仓库固定的 .NET SDK 9.0.320。
- 19 个相关测试模块共 236 项：235 通过，1 项因缺少原生游戏引用跳过。包括所有本轮修改的卡牌合同、178 个牌面的文案核对、付费/回收/重演/持续能力观察结果比较器及 runner 路由。
- B04 的 SDK 独立 fixture 实际编译生产卡牌代码，21 个检查通过，包含基础和升级的格挡→攻击→迎战顺序及战斗结束边界。
- 卡牌实现范围核对为恰好 15 张；U21、U27、U34、U38、U40 的卡牌类与基线逐字一致。原生牌面场景枚举由 410 增至 433，仍覆盖 178 个牌面；场景已准备，但未执行游戏内验证。
- `git -c core.whitespace=cr-at-eol diff --check` 通过，保留现有文件换行格式。
