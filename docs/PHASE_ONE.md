# 第一阶段：可运行的核心玩法纵向切片

状态：实施中，未通过游戏验收。目标版本 StS2 0.107.1 / commit 59260271。

## M0 开发运行环境

- 锁定 .NET 9 SDK，隔离安装，不替换系统运行时。
- 核验 Godot 4.5.1 .NET/MegaDot 资源构建需求、RitsuLib 0.6.10 Compat.0.107.1。
- 建立 doctor / build / test / deploy / run / logs / undeploy 入口。
- 最小 DLL 加载探针先验证官方 Mod 初始化，再接 PCK、中文与框架。
- 本机路径与日志不入 Git；不提交游戏程序集，不覆盖原版文件或存档。
- 通过标准：实际游戏日志证明加载，不能以编译或复制成功替代。

## M1 机制决策门

1. 雷伤：非攻击，不受力量/易伤/虚弱，格挡/减免/死亡管线正确，批次和多目标计数不递归。
2. 迎战：遵循 [结算契约](ENGAGE_SETTLEMENT.md)，执行真实 move，核验后续敌方阶段与下一轮，不做擅自语义降级。
3. 领域：按既定 Tier 2 边界逐类验收；任何不支持的敌人行为记录为未支持，不称全覆盖。

## M2 最小完整集合

约 10–14 个卡牌定义及必要兽化衍生牌。包含基础攻防、霆爪、挺身迎战、以牙还牙、雷霆反扑、众敌皆来、领域入口、原生雷伤、不动神躯、兽化入口、迎战完成响应及初始遗物。实际名称/ID/数值以规则参考核验后固定，不能凭方案文字重新定义。

正常起始卡组保持既定设计；开发测试集合与正常发牌隔离。采用当前 clean 动画、V7 卡图与既有非官方运行音效，不依赖官方 Riot 录音。

## M3 回归验收

- 选角、开局、进入与完成战斗、失败退出。
- 连续战斗状态清理，正常与迎战的敌人状态机推进。
- 多段、混合动作、非攻击动作、完全格挡、坚甲、多目标、死亡/反击/召唤边界。
- 单人优先；存档与联机只在实际验证后声明支持。
- 不使用机制时保持原流程，移除本 Mod 后原游戏能启动。

## 测试证据分层

- 自动逻辑测试：资格、窗口、吸收、时长、次数与清理。
- 构建与契约测试：版本、manifest、资源、本地化、程序集入口。
- 游戏集成：真实伤害/调度/动画等待/死亡与推进，保存本次日志与用例结果。
