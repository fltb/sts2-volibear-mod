## 完成判定

PR 的目标是合并后能从源码生成完整 Mod，安装后沿游戏正常入口游玩。
实现完成的意思是：假设已实现行为都正确，既定产品范围没有剩余缺项。
正确性另以实际构建、测试和游戏运行结果判断。

维护环境缺少游戏本体，只影响依赖该环境的执行。所有生产代码、构建工具、验收代码、
独立预期和故障诊断入口仍在本 PR 完成。用户本地 Agent 承担实际绑定与运行，发现问题后
可以在本地修复，也可以把报告交回继续修复。未运行的步骤保留“未执行”，不计为通过。

## 构建与 Godot 的依据

用户补充的 [ModTemplate Setup](https://github.com/Alchyr/ModTemplate-StS2/wiki/Setup)
和 [Modding Basics](https://github.com/Alchyr/ModTemplate-StS2/wiki/Modding-Basics)
作为工程接入参考。此仓库固定的目标组合为：

| 组件 | 本 PR 使用 |
| --- | --- |
| StS2 | 0.107.1 / 59260271 |
| Godot 资源构建器 | 普通 4.5.1 stable Mono/.NET |
| SDK | .NET 9.0.320，由 global.json 选择 |
| 框架 | BaseLib 3.4.7，固定发行包摘要 |

模板允许用匹配 MegaDot 版本的普通 Godot .NET 作后备。本仓库保持已经选定的普通
Godot 4.5.1 路线，实际游戏继续由安装的游戏引擎运行。工程提供 `Volibear.sln` 供 IDE 打开；
C# 直接引用游戏提供的程序集，PCK 在独立资源工程中生成。资源工程只包含 GDScript 和资产，
其脚本以源码导出，构建后在 Godot 中挂载并核对实际字节。

发布入口是 `tools/local_delivery.py`，它执行模板所述的完整发布链：C#、PCK、JSON、部署与打包。
仅执行 `dotnet build` 不会更新图片/文本/场景资源。每次完整交付均重新构建当前 DLL 与 PCK，
避免混入旧产物。运行时还在安装任何 Volibear 补丁前核对游戏版本与构建号。

## 实施与验收顺序

1. 对照上表核实生产入口。发现确定缺陷先修复，给出能够暴露该缺陷的回归。
2. 完成当前源码的独立逻辑、真实 Harmony 和 Godot 资源检查。
3. 本地 Agent 执行 `--verify-release`：全量回归、原生流程/表现、进程重启、两个网络客户端。
   任何必需的程序集检查被跳过，或任何游戏阶段失败，都不能生成本次成功安装包。
4. 按报告中的首个真实错误修复，再跑受影响范围和完整交付入口。
5. 检查最终安装文件、模型身份、资源和版本一致后交付。PR 追加提交；不改写 main。

单人批次复用一个后台游戏进程；跨进程恢复才使用 prepare/resume 两个进程；多人使用两端。
无 Mod 对照用于区分游戏本来的退出噪声。所有验证使用新建隔离资料目录，不发送 OS 键鼠、
Viewport 输入或按钮伪信号。实际出牌和选择仍经过原生动作及选择接口。

跨 Mod 支持以共享命令、公开钩子和已核对的正式敌人适配为边界。无法证明来源的第三方
直接状态写入保留原生结果并诊断，不能误删玩家收益；新正式敌人缺失则必须补实现。
不能给任意第三方私有状态机作无条件兼容保证。
