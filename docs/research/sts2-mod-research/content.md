## 0. 关键结论（先看这 6 条）

1. **规模与基础数据自洽**：89 = 87 主卡 + 2 兽化形态；奖励池 83（普通 24 / 罕见 36 / 稀有 23），基础 4 + 衍生 2 不入池。初始生命=最大生命=80（A20：最大 75、初始 68），初始卡组 10 张（打击×4/防御×4/霆爪/挺身迎战），初始遗物「不灭狂雷」每战每回合首次**完成**迎战抽 1，Boss 遗物「万古不灭」替换后抽 2。
2. **"雷伤"不是原生概念**：它是"非攻击、可格挡、不吃力量/易伤/虚弱"的卡牌伤害批次，按**批次**计 1 次（全体 1 批=1 次，多段=多次）。StS2 侧应走 `CreatureCmd.Damage` + 非 `Move` 的 `ValueProp`（建议 `DamageProps.cardUnpowered`），必须先做 1 个实机验证：力量/易伤是否真的不生效、是否被格挡。
3. **"迎战"是唯一平台级不可确定项**：StS2 的敌人动作发生在敌方阵营回合（意图→执行）。方案是**在玩家回合内直接驱动 `MonsterModel.MoveStateMachine`/`PerformMove` 执行当前意图**，并给该敌打"本轮已行动"标记让正常敌方阶段跳过。官方模型存在、但属于非设计用法：状态机/动画/多人同步/阵营门控都有风险，**需要先做一个技术原型**（见 §5.3 与 §7）。
4. **"领域全压制"按字面做等于让敌人 AI 失效**（复活/阶段/限伤/限牌/无敌/不可选/改写/取消升级全部禁用）。模拟器已经把它细化成"只压制对敌人有利的效果、保留普通攻击/直接力量/直接格挡/战斗事实与全部负面效果"，且用 `EffectKind` 分类门控实现（`mechanics/domain.ts:35-52`）。StS2 建议采用**分档压制 + 逐敌种白名单**，v1 只覆盖 9 类一次性/持续性特效，不碰敌人普通 AI（见 §5.4）。
5. **用户修订卡表（2026-10-27）与定稿（2026-10-28）有 13 张牌、25 处牌面/数值字段差异 + 5 条规则级差异**：U21 触发频率（每回合 1 次→每 2 次雷伤）、C26/U40 返能限次（共享 1 次→不限次）、U15 消耗是成本还是牌效（成本→牌效）。**建议全部以 2026-10-28 定稿为准**；用户表的机制**定义**（关键词表、领域附着时机、迎战完成条件、兽化实体继承、费用结算）仍应作为术语与边界的依据，见 §4 裁决表。
6. **"雷势"是纯数值、无上限、本战不衰减不消耗**：独立于力量；只有 6 个来源（C25/U29/U26/U04/R28/R17），每点只加"雷伤"不加攻击。它与"强化 N"（每牌本战固定加伤）是两套独立乘法/加法体系，不要合并实现。

## 2. 逐卡矩阵（89 张）

### 2.1 阅读口径

- **类型**：攻击 / 技能 / 能力（metadata type 0/1/2）。**"雷法"不是第四种类型，而是技能的子类标签**：判定条件 = 技能牌且牌面直接造成雷伤（`cards/programs.ts:33-34` + `cardConfig` 在 `metadata.type===1 && hasNativeLightning` 时声明），全表 10 张：C24/U28/U35/U37/U40/R07/R09/R17/R23/T02。
- **费用**：`基础／升级`；`X` = 支付当前全部能量（metadata 内部记 `-1`，X 牌不吃数字减费）。
- **稀有度**：基础 / 普通 / 罕见 / 稀有 / 衍生（衍生 = 兽化形态，不入奖励池、非永久牌组）。
- **目标**：单体（需要选中敌人）/ 全体敌人 / 随机敌人 / 自身或无目标。**注意**："单体"指"攻击或迎战的选中目标"；带"对全体造成雷伤"的牌仍可以是单体目标牌（如 B03/C03/U28）。
- **消耗**：`否` / `是` / `基础后（升级不消耗）`（即基础消耗、升级不消耗，仅 C14/U14）/ `升级后`（基础不消耗、升级消耗——本表无此组合）。
- **保留 / 重演**：基础卡表中没有"保留"或"重演"关键词的牌；保留由 C19 授予所选攻击牌，重演由 U11 授予本回合下一张攻击。矩阵中 `retain/ethereal/innate = false` 是所有 89 张的静态值。
- **实现要点**一列是给 C# 实现的单句规则摘要，细节时序见 §3 与 §6。
- **跳号**（不是遗漏）：C16/C23；U09/U16/U18/U22/U30/U33；R03/R04/R11/R15/R19/R20/R22/R26 均不存在于定稿。

`code`（B/C/U/R/T 编号）、`runtime_id`（`VOLIBEAR_<code>`，与美术 `CARD_BINDINGS.md` 可直接对齐）、`name`、`type`/`type_code`、`rarity`/`rarity_code`/`rarity_slug`、`pool`（`basic|reward|token`）、`cost`（base/upgraded/is_x）、`target`、`needs_selected_enemy`、`single_target_attack`、`strike_tag`（原版"打击"标签，仅 B01）、`lightning_spell`（雷法）、`text.base/upgraded`、`keywords`、`exhaust.base/upgraded`、`retain/ethereal/innate`（静态 false）、`replay_grantable`（该牌可作为 U11 重演目标，= 攻击牌）、`after_use`（`discard|exhaust|deployed_power`）、`internal_cost_check`（metadata 原始费用，-1 = X）、`implementation`。

## 3. 机制规格（Mod 实现依据）

> 每一节格式：**定义/触发时点 → 结算顺序 → 跨回合/跨战斗 → 需要持久化的字段 → 与 StS2 原生状态的关系 → 模拟器出处**。
> "存档"指 Mod 需要在战斗存档里落盘的字段（StS2 用 PowerModel 的实例字段或 RitsuLib RunSavedData/内部数据实现）。

### 3.1 雷势（thunder momentum / `stormCharge`）

- **定义**：角色独立增幅，每点使**每段雷伤 +1**；不是力量、不作用于普通攻击、不进原生 PowerModel 的加成链。无上限、不自动消耗、本战不衰减。
- **触发时点（6 个来源，全部在支付费用之后）**：
  | 来源 | 数值 | 时点 |
  |---|---|---|
  | C25 雷引 | 1／2 | 牌效内立即获得 |
  | U29 雷霆渐盛 | 2／3 | 能力部署时 |
  | U26 愈战愈烈 | 每实例 1／2 | 每回合第 2 张**实际攻击**支付后、牌效前 |
  | U04 战痕 | 每实例 1 | 每回合**首次完成迎战**后 |
  | R28 熊灵侵染 | 每实例 1 | 每回合**首次实际打出兽形**支付后、牌效前 |
  | R17 天雷决 | 支付 X（升级 X+1） | 牌效内先得雷势，再逐段雷击 |
- **结算顺序**：获得即写入，随后所有雷伤读取实时值；多份来源按事件顺序累加；U21/U34/U02/R18 等"每次雷伤"响应读取的是**结算后的雷势**（因为每次雷伤批次单独计算金额）。
- **跨回合/跨战斗**：跨回合保留；战斗结束随战斗实体销毁（不跨战斗、不写永久牌组）。每回合独立的只有"雷伤次数"（`strikes`），不是雷势。
- **存档字段**：`{battleId, owner, amount, strikes, strikesTurn}`；`amount` 本战累加，`strikes` 在回合切换时逻辑归零（读取时 `strikesTurn!==当前turn` 即视为 0，无需写回）。
- **与 StS2 原生状态关系**：与 `StrengthPower` 完全独立；不要用力量实现。若用 PowerModel 承载，注意它不应参与 `ModifyDamageAdditive`（否则会加成普通攻击）。
- **模拟器出处**：`mechanics/storm-charge.ts:11-16`（状态/读取）、`:27-33`（gain/noteStrike）、`DEVELOPMENT.md:37`。

### 3.2 雷伤（lightning damage）

- **定义**：卡牌牌面"造成 N 雷伤"直接产生的**非攻击伤害批次**。金额 = 牌面原生值（含"强化 N"与 U12 本轮增幅）+ 当前雷势。**不受力量、易伤、虚弱影响**；**受格挡吸收**；进入普通伤害的减免/限伤/预防/死亡管线；可以完全格挡、可以击杀。
- **"每次完整结算计 1 次"的计数规则**：
  - 一次 `lightning.resolve`（一个批次）无论命中多少敌人 = **1 次**；全体雷伤 1 批 = 1 次；多段（C22/R23/R08/U31/R17）每段 1 批 = 多次。
  - 空目标列表（无存活敌人）不产生批次、不计数。
  - 计数在命中结算**之后**、`settled` 事件**之前** +1（`mechanics/lightning.ts:26-37`），因此 U21（第 2/4/6… 次）读到的是含本批的值。
  - 领域附雷、U02 每段联动、U34 每批格挡、R18 雷池、C14 反雷全部以"批次"为粒度，**不是每敌人粒度**。
- **受哪些修正影响**：
  | 修正 | 是否影响雷伤 | 说明 |
  |---|---|---|
  | 力量 / 易伤 / 虚弱 | ❌ | 只作用于 `attackAmount`（普通攻击） |
  | 雷势 | ✅ 每点每段 +1 | 独立加法 |
  | 强化 N（R06/U10 的 damage-training） | ✅ 生效于**卡牌自身**原生雷伤（`thunder()`，含"对该目标"与"对全体"） | 不作用于领域附雷（固定 4） |
  | U12 原始力量 | ✅ 本轮所有自身雷伤 +当前正力量 | 独立增幅，覆盖敌方阶段 |
  | 格挡 / 减伤 / 限伤 / 预防 | ✅ 走普通伤害管线 | 与攻击相同 |
  | 敏捷 / 脆弱 | ❌ | 只作用于格挡获取 |
- **结算顺序**：先算金额 → 依次对每个目标 `damage.hit`（格挡→生命损失）→ 若有目标可受伤则判定战斗结束 → `noteStrike`（+1 次）→ 发 `settled` 事件（驱动 U21/U34/雷甲等响应）。
- **跨回合**：不持久；每次重新计算。
- **存档字段**：无（瞬时），但"本回合雷伤次数"需存 `strikes`（见 3.1）。
- **StS2 关系**：原生只有 Move（攻击）/Unpowered（可格挡、无力量）/Unblockable（不可格挡 HP loss）三档。雷伤应映射为**可格挡但非攻击**的一档，不能映射成 `Move`（否则吃力量/易伤），也不能映射成 `HpLoss`（否则不可格挡）。见 §5.2。
- **模拟器出处**：`mechanics/lightning.ts:18-44`、`rules/damage.ts:31-59`、`rules/attributes.ts:24-29`、`content/powers/attributes.ts:23-37`。

### 3.3 领域 N（domain）

- **定义**：一个战斗唯一的状态 `{battle, until|null, drawnTurn, lastPlay}`；展开/延长 N 轮（永久 = `until=null`）。提供三件事：**攻击附雷**、**敌方特效压制**、**抽牌净化**。
- **时长与到期（精确到抽牌阶段）**：
  - `open/extend`：`until = max(当前turn, 已有until) + N`（永久域不降级，`null` 保持 `null`）；同一战斗重复展开是**叠加剩余轮数**，不是覆盖。
  - `active` 判定：`until===null || 当前turn < until || (当前turn === until && drawnTurn < 当前turn)`。
  - 结束时点：下一玩家回合的**正常起手抽牌之后**（`turns.playerPostDrawRelics` 阶段）写入 `drawnTurn=turn`，此后失效。所以"领域 1"覆盖：本玩家回合 → 敌方阶段 → 下一玩家回合起手抽牌期间；起手抽牌结束立刻扣掉。
  - R28 的"起手可选兽化"在 `playerPostDrawPowers`（更晚），因此它读到的领域状态是**已扣时**后的状态（测试：`R28起手兽化后的抽牌读取已到期领域`）。
- **攻击附雷（核心）**：
  - 触发条件：领域 active + 本次**实际出牌**是攻击牌 + 该牌首个"普通攻击命中"结算后；`triggerOnUse && !purgeOnUse`；同一 `playId` 只触发一次（`lastPlay`），**重演共用同一次机会**。
  - 金额：固定 `4 + 当前雷势 + U12 增幅`（**不吃强化 N**），对全体造成一笔雷伤（= 1 次雷伤计数）。
  - 全体攻击的一段：跨全体只发 1 次攻击段事件 → 只附雷 1 次。多段攻击每段都有"命中"，但只有第一段触发（`lastPlay` 已写）。
  - 先开领域后攻击的牌（C05）同牌立即享受附雷；先迎战后补攻击的牌（C10）附雷发生在**补充攻击命中时**（即吸收量已确定之后）。
  - 雷伤本身不触发附雷（不是攻击），U02 联动也不递归。
- **压制（不是"关闭 AI"）**：
  - 模拟器用内容层 `effectPolicy.allowed` 门控：当效果 `actor` 属于敌人、且**相对玩家的极性为正**（对敌有利）时，只允许 `Attack/Block/Strength/BattleFact` 四类效果通过，其余取消（`mechanics/domain.ts:35-52`、`effect-policy.ts`）。
  - 保留：普通攻击、当前/直接力量、当前/直接格挡、必要战斗事实与清理；敌人自身的不利效果（虚弱/易伤/缓慢增伤/瞬态减攻/飞行层数损失/眩晕/多层护甲损耗）继续生效；混合能力逐项判断，保留不利部分（如守护者受伤计数、转防打断、阈值重建保留，但附带的被动 20 格挡与尖刺外壳压制）；敌人施加给玩家的负面效果**仍压制**（属于敌方有利）；状态到期清理照常。
  - 展开领域时取消 pending 复活（清 `halfDead`）；已消费的一次性复活/阶段/改写事件进入 canceled 终态，离开领域后不得补发；领域内不延迟胜利（生命为 0 且无敌人立即胜利）。
- **抽牌净化**：真实"抽到"状态/诅咒牌（type 3/4）时：抑制其自身效果 → 消耗 → 补抽 1 张。检索/回收/移动不是抽牌事件，不受影响；敌源状态（Burn 等）每次执行都检查压制。
- **叠加规则**：重复展开只叠加剩余轮数；永久领域不降级；领域状态是战斗唯一实体（重复=错误）；`lastPlay` 每此出牌更新。
- **存档字段**：`{battleId, until (int? = 永久), drawnTurn, lastPlay(playId)}`；另需一张"本次出牌是否已触发附雷"的 playId（就是 lastPlay）。
- **与原生状态关系**：影响 `Block`（保留直接格挡）、`Strength`（保留直接力量）、`Vulnerable/Weak`（玩家施加给敌人的照常；敌人施加给玩家的被压制）、以及敌方 Power/意图。**StS2 里等于要改敌人 AI 的产出层**，见 §5.4 替代方案。
- **模拟器出处**：`mechanics/domain.ts:23-91`、`DEVELOPMENT.md:39-41,53`。

### 3.4 迎战（engage）与吸收（absorb）

- **定义**：**沿用本牌目标**，立即令该敌执行"本轮尚余行动"（即它已经选好、但还没执行的意图）。每个敌人**每轮共享 1 次行动机会**；正常敌方阶段会跳过已用掉机会的敌人。
- **7 张迎战牌**：B04、C04、C10、C11、U28、U35、R09；均**自动执行**（没有"可选"分支；模拟器保留了旧可选接口但已 inert）。
- **各牌结算顺序（严格）**：
  | 牌 | 顺序 | 关键点 |
  |---|---|---|
  | B04 | 格挡 → 攻击 → 迎战 | 攻击可能先杀死目标 → 迎战空过 |
  | C04 | 攻击 → 施加 1 虚弱 → 迎战 | 虚弱先于敌人行动，影响其攻击 |
  | C10 | 格挡 → 迎战(记录 absorbed) → 造成 6/9 + 该目标 absorbed 的攻击 | 吸收为 0 时按基础值 |
  | C11 | 格挡 → 迎战 | 技能版 |
  | U28 | 格挡 → 迎战(累计 absorbed) → 全体雷伤 4/6 + 总吸收 | 雷法；伤害是雷伤不是攻击 |
  | U35 | 格挡 → 全体雷伤 3/5 → 迎战 | 雷击可能先杀目标 → 迎战空过 |
  | R09 | 格挡 → 依次迎战全体(累计 absorbed) → 全体雷伤 = 总吸收 | 每敌各用一次机会 |
- **"完成"的判定**：`动作实际开始 && 玩家存活 && 战斗继续` 才算完成迎战；只有完成后才发 `engageCompleted`，才触发不灭狂雷/U04/U19/R18 等"迎战后"响应。敌人本轮已行动过 → `performed=false` → **不触发任何"迎战后"响应，吸收=0**。
- **吸收**：本次迎战期间玩家以**格挡吸收的伤害总量**（含完全格挡；坚甲时格挡不被消耗但吸收量照算）；多目标（R09）累加；未实际迎战=0。吸收是本次出牌的瞬时值，**不入存档**。
- **目标已行动 / 多目标 / 死亡 / 意图**：
  - 目标本轮已行动：本次迎战空过（不重复结算、不计吸收、不触发 after-engage）。
  - 多目标：R09 逐个迎战，按板面顺序；某个敌人已行动则跳过（累计其 0）。
  - 目标死亡：牌内先行的攻击/雷伤击杀目标后再迎战 → 空过；迎战过程中玩家死亡 → 战斗结束，后续牌效（C10/U28/R09 的追加伤害）跳过。
  - 意图：使用**当前已选定的意图（本轮尚未执行的行动）**，不重新 AI 选择；若敌人没有可执行行动/被眩晕/离场则空过。
- **存档字段**：每敌 `{opportunityRound/turn, acted/claimed}`（模拟器存 `opportunityTurn` 与 `actedRound`，交换敌人/复活要重置）；`absorbed` 只在本次结算内。
- **StS2 关系**：这是**跨阵营时序**操作，见 §5.3；在 StS2 里"敌人本轮是否已行动"不是原生公开状态，需要 Mod 自己记录（建议挂在敌人身上的隐藏 Power 或 run/combat 数据）。
- **模拟器出处**：`mechanics/engage.ts:18-33`、`cards/engage.ts:26-63`、`rules/enemies.ts:45,79,95-101`、`DEVELOPMENT.md:42`。

### 3.5 兽化（beast transform）

- **定义**：手牌**攻击牌** → 裂骨之爪 T01（爪形）；其他牌 → 风暴之躯 T02（躯形）。**沿用原牌实体**：永久牌组中的原牌不变，升级/临时减费/保留继承，打出形态后**消耗**，战斗结束恢复原牌。
- **转换实现（语义）**：
  1. 若该牌已是兽形（shape≠0）→ 不重复转换、不发转换事件（但仍可得到本次"减费 1"优惠，见 R27/R29 规则）。
  2. 生成形态代理牌（T01 或 T02），`upgraded` 继承材料；原牌行为重定向到代理、原效果被抑制。
  3. 原牌费用被设为形态基础费 1，并保留既有临时减费（`costForTurn = max(0, 1 - max(0, oldCost - oldCostForTurn))`），随后由转换效果再给"本回合下次 -1"优惠 → 实际常为 0 费。
  4. 发 `beastChanged` 事件（R28 的"首次兽化抽牌"、形态显示等据此响应）。
- **批量兽化顺序**：**先完成取牌并冻结集合** → 逐张转换；转换过程中触发抽牌得到的新牌**不进入本批**；`R29` 覆盖集合内全部牌（上限=手牌上限 10）并各减费 1。
- **减费/附带**：U41/U42/U43/R30/R29 转换后各给 -1（本回合下次）；R27 只给爪形 -1，躯形改为各获得 4 格挡；R27 数量"至多 2/3"可 0 张。
- **变身牌去向**：形态牌本身 `消耗`；原牌战后恢复（永久牌组不变，`masterGrowth` 永远为 0）。
- **升级继承**：材料升级 → 形态升级（用 T01/T02 升级面数值）。
- **存档字段**：每张被转形态的牌 `{battle, owner, cardId, proxyCardId, shape(1|2)}`；原牌的 mutable 费用/费用修正/抑制标记；代理牌实体引用。R28 每实例还需 `{lastTransformTurn, lastShapeTurn, lastClawTurn}`。
- **与原生状态关系**：改变的是**卡牌身份与费用**；不改变玩家力量/格挡等。兽形牌的"爪形/躯形"判定用于 R28/R30 的挂钩。
- **模拟器出处**：`mechanics/beast.ts:15-40`、`cards/beast.ts:29-39,52-77`、`cards/metadata.ts:114-115`、`DEVELOPMENT.md:43-44`。

### 3.6 检索／回收（search / recover）

- **检索**（从抽牌堆）：按条件筛选（攻击 / 雷法 / 技能 / 任意），手牌空间 = `10 - 当前手牌数`；`max = min(参数, 空间)`；空间 ≤0 → 直接跳过。可选类（"至多"）最小值 0，非可选为 `min(参数, 空间, 候选数)`。**执行前先确定抽牌堆顺序**；**不是抽牌事件**（不触发抽牌净化/抽牌响应）。
- **回收**（从弃牌堆）：C15 单张（攻击**或**雷法），R10 至多 3/4 张**攻击**，每张回收后给"本回合下次 -1"；同样先占手牌位。
- **牌表**：C07（检索 1 攻击）、U39（检索 1 雷法）、U43（检索 1 任意）、R25（检索至多 2 技能，可 0）、C15（回收 1 攻击或雷法）、R10（回收至多 3/4 攻击）。
- **跨回合**：无状态；"至多"选择可放弃。
- **存档字段**：无（选择即结算）。
- **模拟器出处**：`cards/beast.ts:41-51`（search）、`cards/selections.ts:57-85`（recover）。

### 3.7 减费（4 套机制，不可混用）

| 种类 | 牌 | 规则 |
|---|---|---|
| A. 通用"下一张攻击减费 N" | C25(1)、U32(1/2)、U14(迎战牌 1，独立类) | 本回合下一张**实际打出**的攻击（U14 为"下一张声明迎战的牌"）费用 -N；同类待用优惠**取最大值、不叠加**；实际打出即消费；只作用于数字费用（X 牌无效），最低 0 |
| B. 单牌优惠（-1） | C15/R10 回收、U25 抽到的攻击、兽化所得形态 | 对**指定牌**本回合下一次实际打出 -1；同类不叠加；该次重复效果共享 |
| C. 动态费用 | U07（本回合对该目标每打出 1 张攻击 -1）、U38（本回合每 1 次雷伤 -1） | 实时读取、最低 0；U07 不计自身本次 |
| D. 基础费变更 | 兽化形态 | 形态基础费 1 + 保留原临时减费 |

- **顺序**：基础费（含升级/X）→ 固定修正（A/B/D）→ 动态修正（C）→ 最低 0。X 牌支付当前全部能量，不吃任何数字减费。
- **跨回合**：A/B 都是"本回合"有效，回合结束失效；D 随形态牌存在（形态牌消耗）。
- **存档字段**：A/C 存 `{battle, turn, amount, consumedPlayId}`、B 存 `{battle, turn, cardId, consumedPlayId}`；都按战斗回合门控。
- **模拟器出处**：`mechanics/attack-discount.ts`、`mechanics/next-play-discount.ts`、`mechanics/engage-preparation.ts`、`cards/uncommon.ts:31-35`（U07）、`cards/storm.ts:19-22`（U38）。

### 3.8 咬痕（bite mark）

- **定义**：暴怒撕咬 U08 命中后留下的**敌人标记**，按 `(玩家, 敌人)` 实体保存，持续本战；同一敌人可叠加多次但判定只看"是否存在"。
- **触发时点**：U08 的普通攻击**命中后**登记（完全格挡/致死也成立）；**同一次重演不读取刚施加的标记**（标记记录首次施加的 `playId`，查询要求 `firstPlay !== 当前playId`）。不同敌人的标记互相独立。
- **结算顺序**：U08 先格挡 → 攻击（伤害计算时读"出牌前"是否已有标记：有则 +6/9）→ 命中后施加标记。
- **跨回合/跨战斗**：跨回合持续本战；战斗结束清除（不跨战斗）。
- **存档字段**：`{battleId, ownerId, enemyId, firstPlayId}`。
- **与原生状态关系**：等价于一个只有 U08 读取的敌人 Power/标记，不参与原生伤害链。
- **模拟器出处**：`cards/growth.ts:12-23`、`DEVELOPMENT.md:51`。

### 3.9 反雷 N（counter-lightning）

- **定义**：C14 获得的状态：本轮内每承受**一段敌人攻击**后，对攻击者造成 N 雷伤；**完全格挡也触发**。
- **触发时点**：任意 `damage.resolved` 且 `attack=true` 且目标是玩家、攻击者属敌方、双方可受伤、战斗未结束。多段攻击每段各触发一次。反击伤害是**单体雷伤**（吃雷势/U12，不吃力量易伤；可被格挡）。
- **持续**：`until = 打出时的回合 + 1`，即覆盖本玩家回合的敌方阶段与下一玩家回合开始前；**不随领域延长**；多次打出各自独立、不合并。
- **存档字段**：`{battleId, ownerId, untilTurn, amount}`。
- **模拟器出处**：`mechanics/thunder-guard.ts:15-46`。

### 3.10 蓄势 N / 强化 N（两套独立加伤）

| | 蓄势 N（C19） | 强化 N（U10/R06） |
|---|---|---|
| 作用对象 | **指定一张攻击牌** | 一张牌 / 本战全部攻击与雷法 |
| 效果 | 该牌**下次实际打出**时每段**固定攻击伤害** +N（不含动态攻击如 U05/R07，不含雷伤） | 该牌本战每段自身攻击伤害与**原生雷伤** +N（含动态攻击） |

| 附加 | 同时给该牌**本场保留** | 无 |
| 叠加 | 同一牌多次蓄势按来源累加 | 同牌多次强化累加 |

### 3.11 重演（replay）

- **定义**：U11 使本回合下一张实际打出的攻击**额外完整结算一次牌效**；不是"再次打出"——共用目标、已支付 X、出牌前条件与本次领域附雷机会；不增加"实际打出次数"（U26 只算 1 次，U25/咬痕按 playId 去重）。
- **每段伤害独立结算**；每次完整重演都会执行"牌面资源授予"（如抽牌、格挡、雷势）。
- **存档字段**：`{battle, turn, consumedPlayId}`。
- **StS2 关系**：原生有"本牌打出 N 次"（`BaseReplayCount`/`ModifyCardPlayCount`）——语义接近"重演"但可能重复触发 OnPlay 与出牌事件，需要验证差异；见 §5.7。
- **模拟器出处**：`mechanics/repeat.ts`、`cards/uncommon.ts:51`。

### 3.12 汲取（drain）

- **定义**：U24 造成 3 雷伤后，按该段**实际造成的生命损失**回复生命（完全格挡/溢出击杀都只按真实损失）。
- **顺序**：攻击 21/28 → 记录目标 HP → 雷伤 3（+雷势/U12/强化）→ `heal = max(0, before - after)`。
- **存档**：无。
- **模拟器出处**：`cards/lethal.ts`、`cards/s2-operations.ts:17-30`。

### 3.13 留甲 N（retain-block）

- **定义**：U03 能力。从**打出后的下个回合**开始，回合开始的格挡重置改为 `block = block - min(N, block)`（即保留 max(0, block-N)）；N=6（升级 3，升级反而更好）。

- **叠加**：同名能力重复获得取**较低层数**（`min`），不累加。
- **存档字段**：`{battleId, ownerId, level, deployedTurn}`（部署当回合不生效）。
- **模拟器出处**：`powers/standing.ts:13-40`。

### 5.1 总体建议

- **用 RitsuLib 的内容注册 + 模板**（`ModCharacterTemplate/ModCardTemplate/ModPowerTemplate`、`[RegisterCard]/[RegisterCharacter]/[RegisterPower]`、content pack、`CardKeywordOwnedByLocNamespace`）作为骨架；BaseLib 作为依赖与补充（`CustomCardModel` 等）；两者不要混用同一内容的注册源（[RitsuLib 文档](https://sts2-ritsulib.ritsukage.com/guide/content-authoring-toolkit)、[BaseLib/ModTemplate 指南](https://github.com/Alchyr/ModTemplate-StS2/wiki/Modding-Basics)）。
- **所有卡牌行为只走命令**（`DamageCmd/CreatureCmd/PlayerCmd/CardPileCmd/PowerCmd/CardCmd`），不直接改数据结构；89 张卡是"OnPlay 命令序列 + Power 钩子"的组合，和模拟器的 `compose(...)` 结构一一对应。
- **状态承载优先级**：原生 Power（力量/虚弱/易伤/反雷）→ 自定义 PowerModel（领域/雷势/兽化/蓄势等）→ 卡牌 mutable 字段（费用、形态重定向）→ RunSavedData（跨战斗不需要；本作全部战斗内）。注意 StS2 战斗存档会序列化 Power 实例字段，自定义 Power 的字段必须可序列化。

### 5.3 迎战可行性评估（必须做原型）

- **平台事实**：StS2 的敌人行动在敌方阵营回合执行（`CombatManager.SwitchFromPlayerToEnemySide` / `AboutToSwitchToEnemyTurn`），敌人是 `MonsterModel` + `MoveStateMachine`，当前意图由 `AbstractIntent`（Attack/MultiAttack/Buff/Debuff/Defend/Heal/Status/Summon/Escape/Stun）表达。**没有公开的"让某个敌人在玩家回合执行当前 move"的官方入口**（至少 sts2.dll 文档中没有；`MonsterModel` 的公开成员只有 MoveStateMachine 等少量）。
- **可行路线（推荐）**：在 `OnPlay` 里
  1. 读取目标 `MonsterModel.MoveStateMachine` 的当前 move / 意图；
  2. 直接调用其 `PerformMove`（或等价的 move 执行入口）——这是非设计用法，需要 Publicizer/Harmony；
  3. 执行前后用自研 `EngageWindowPower` 标记玩家，`AfterDamageReceived` 累计吸收；
  4. 给目标打隐藏 `EngagedThisRoundPower`，正常敌方阶段在 `BeforeSideTurnStart`/`BeforeEnemyTurn` 检查并跳过该敌（或用 `Stun` 类机制代替"跳过"）。
  5. 多人模式：迎战会让敌方在当前玩家回合行动，必须写进同步事件/使用 `PlayerChoiceContext`，否则会 desync；v1 建议只支持单人。
- **风险清单**：阵营门控（攻击动画/伤害来源是卡还是怪物）、意图显示与消耗、敌方 move 内部对 `CombatState` 的假设、敌方回合计数器、玩家死亡中断、多人同步、与"敌人已行动"原生状态重复。
- **降级/替代方案（按推荐顺序）**：
  1. **"提前结算"**：不真正执行 move，而是把当前意图拆成等价命令（Attack 意图→`CreatureCmd.Damage` 对玩家；Buff/Defend 意图→`PowerCmd.Apply`/`CreatureCmd.GainBlock`），然后标记该敌本回合已行动。可控性最高，但需要覆盖所有意图类型（可控且可测试）。
  2. **"眩晕 + 立即行动"**：给目标 `StunPower`/跳过其下回合，同时立即执行（等价于把敌人下回合行动提前）。
  3. **规则改写**：把"迎战"改成"本回合结束时敌人立即行动一次，且其下回合跳过"——保持"敌人多打一次"的经济性，但时序不同，必须经用户确认。
  4. **不可行时**：把 7 张迎战牌改为"造成等同敌方当前意图攻击力的伤害/格挡"（失去吸收机制），属于破坏设计，不建议。
- **结论**：迎战是**唯一必须做技术原型**的机制；原型只需验证"玩家回合内让 1 个敌执行 1 次攻击 move + 玩家格挡结算 + 敌方阶段跳过"。

### 5.4 领域"全压制"的替代方案（分档）

按"不改敌人 AI、只拦特定输出"的原则分三档，建议 v1 只做 1-2 档：

| 档 | 覆盖对象（模拟器清单） | StS2 实现 | 风险 |
|---|---|---|---|
| A. 一次性事件（推荐 v1 全做） | 复活/半血重生、阶段转换、分裂、召唤、改写卡牌、取消升级 | 在对应钩子拦截：`ShouldDie`/`AfterPreventingDeath`（复活）、`ShouldStopCombatFromEnding`、`ShouldAllowHitting`、`AfterCreatureAdded`（召唤）、`ModifyCardBeingAddedToDeck`（改写） | 中 |
| B. 持续增益（推荐 v1 做可枚举的） | 限伤（`ModifyDamageCap`）、无敌/不可选（`ShouldAllowHitting`/`ShouldAllowTargeting`/`IntangiblePower`）、被动力量/格挡（`ModifyPowerAmountGiven` 对敌来源过滤）、尖刺/反伤（`ModifyDamageAdditive` 来源过滤） | 在对应钩子判断"来源=敌人 && 领域 active" → 归零/跳过 | 中-高 |
| C. 行动层（不建议 v1 做） | "禁用敌方全部特殊能力"=重写 AI 产出 | 需要拦截 `MonsterModel` 的 move 选择或 `PerformMove`，等于自研敌人行动层 | **高（等于让敌人 AI 失效，且大量敌人会卡死）** |

**必须给用户的裁决**：是否接受"领域只压制 A+B 档，不压制敌人普通 AI/意图层"？如果不接受，Mod 需要一整个"敌人行为改写层"，工作量与风险会超过其余 88 张牌之和。

### 5.5 兽化实现注意（StS2）

- 推荐用"**生成形态牌 + 从手牌移除原牌 + 记录映射**"：`CardModel.CreateClone`（继承 upgrade）→ `CardPileCmd.AddGeneratedCardToCombat` → 手动同步 `EnergyCost`/`TemporaryCardCost`/`ShouldRetainThisTurn`；战斗结束原牌不变（战斗牌本来就会还原）。
- 不推荐直接改原牌 behavior（需要 patch 牌效分发且容易漏 `CardPlay` 校验）。
- 关键坑：`CardModel` 是模型实例，复制品必须登记到 combat state 才能存档/读档；"减费 1"用 `TemporaryCardCost` 而非改 `EnergyCost`（后者可能被升级/存档写回）。

### 5.6 重演实现注意

优先验证原生 `ModifyCardPlayCount` 的语义：
- 如果它只是"效果结算 N 次"（类似 Echo Form/双发），直接可用；
- 如果它重新走完整 `OnPlay`（重复付费、重复"打出时"事件、重复卡牌去向），则与"重演不算重新打出"冲突，需要改为在卡牌 `OnPlay` 内部对自己 `compose` 序列做二次执行（自研 `ReplayOnce` 标记 + 每张牌的分段执行器），成本较高。

### 5.7 其他原生映射要点

- 易伤/虚弱/脆弱/敏捷/力量：直接用原生 Power，不要自定义；雷伤链路要确保**不经过**它们。
- 敌方"缓慢增伤/飞行/多层护甲"等负面效果：领域内必须继续生效（不要误伤）。
- 状态/诅咒牌类型：原版 `CardType.Status/Curse` 对应模拟器 `type 3/4`，抽牌净化用这两个类型判断。
- 消耗/保留/虚无/固有：原生 `CardKeyword` + `ExhaustOnNextPlay`/`ShouldRetainThisTurn`；本角色 20 张消耗牌、无虚无/固有。


## 6. 边界情况清单（Mod 对齐用）

> 来源：模拟器测试与实现（`tests/volibear-content.test.ts:229-315` 的 89 个用例、`tests/volibear-flow.test.ts`、以及 `mechanics/*`）。这些是"补充审判定"的时序细节，Mod 实现与自测建议逐条覆盖。

### 6.1 领域/雷伤计数

1. 领域附雷**每张实际出牌 1 次**：多段攻击（C02）、全体攻击（一段跨全体）、重演均共享同一次机会（`领域双爪只附雷一次`、`领域重演共享一次附雷`）。
2. 先开领域再攻击的同牌立即享受附雷（C05）；先迎战后补攻击的 C10，附雷在补充攻击命中时。
3. 附雷金额 = 4 + 雷势 + U12 增幅；**不吃强化 N**。
4. U02 按"普通攻击段"触发：多段每段 1 次、全体一段 1 次、X=0 零段不触发、重演可再次触发、雷伤不递归、多份 U02 叠加。
5. U02 的雷伤会打到其他存活敌人（攻击目标被击杀也传导）。
6. R08 的 4 次随机 = 4 攻击段 + 4 原生雷伤 + 4 次 U02 = 9 次雷伤计数。
7. R31 顺序：格挡 → 开领域 → 拆目标甲 → 攻击 → 雷伤；附雷在攻击段后结算（进领域后同牌首段）。
8. 领域 open/extend 叠加剩余轮数；永久领域不降级；重复 open(1) 不会重置已有更长时间。
9. 领域 1 的到期在"下一玩家回合起手抽牌之后"；R28 起手兽化读的是扣时后的状态。
10. 领域净化只对真实抽牌生效；检索/回收/移动不是抽牌；已在手牌的敌源 Burn 逐次受门控（领域内被压制，领域外正常）。
11. 领域展开时取消 pending 复活；已消费的一次性复活/阶段/改写进入 canceled，离开领域后不补发。
12. 领域 active 时不延迟胜利（生命 0 且无敌人立即胜利）。

### 6.2 迎战/吸收

13. 同一敌人每轮只 1 次行动机会：B04 之后再 C11 打同一敌 → 第二次空过。
14. C04 先施加虚弱再迎战（虚弱影响该次敌人攻击）。
15. C10 的追加伤害 = 6/9 + **该目标**吸收量；U28 = 4/6 + **总**吸收（雷伤，全体一笔）；R09 = 总吸收（全体）。
16. U35 先雷击后迎战：雷击若击杀目标，迎战空过。
17. 只有"动作实际开始 + 玩家存活 + 战斗继续"才发完成事件；因此不灭狂雷/U04/U19/R18 只在真正迎战后触发；已行动敌人不触发。
18. 坚甲下 absorbed 照算（格挡未消耗），因此 C10/U28/R09 的追加伤害不因坚甲变低。
19. 迎战会正常消耗玩家格挡并可能致死；中途死亡则后续牌效跳过。
20. R09 对已行动敌人累计 0；对多个敌人逐个按板面顺序。

### 6.3 兽化/形态

21. R29 兽化全部手牌：攻击→T01、其他→T02，各减费 1；先冻结集合，转换过程中抽到的新牌不进入本批。
22. 升级材料 → 升级形态（T01/T02 升级面）；永久牌组不变，战斗结束恢复原牌。
23. 已有兽形不重复转换、不发转换事件（但 R29/R27/R30 的减费/躯形格挡仍按规则结算）。
24. R28 每回合首次兽化后抽 1/2；首次打出兽形在支付后、牌效前获得 1 雷势（影响该形态牌本次雷伤/格挡）。
25. R30：每次实际打出躯形返 1 能量；爪形格挡限每回合首次。
26. R27 可选择 0 张；爪形各 -1，躯形各 +4 格挡。
27. 形态牌消耗；重演形态牌=完整再结算一次（含附雷机会共享）。

### 6.4 迎战遗物/能力

28. 不灭狂雷：每战每回合首次**完成**迎战抽 1；万古不灭抽 2；起手不获得资源。
29. U04：每实例每回合首次迎战后 +力量/+雷势；不要求吸收。
30. U19：每次迎战后抽 1 + 延长领域 1（不限每回合次数）。
31. R18：回合结束 + 每实例每回合首次迎战后各一笔全体雷伤。

### 6.5 费用/减费/X

32. 数字费用在固定减费后最低 0；X 牌不吃数字减费。
33. 同类待用减费取最大值，不叠加；不同类（如 U07 动态 + C25 优惠）可叠加。
34. U07 可把自己减到 0；只算"本回合此前对该目标打出的攻击"，不含自身本次。
35. U38 费用随本回合雷伤次数动态下降（结算时点即当前值）。
36. U14 只影响"声明迎战"的牌，实际打出即消费；基础消耗/升级不消耗。
37. R17：支付当前全部能量，X有效=X+升级;先获得全部雷势，再逐段雷击；升级时 0 能量也获得 1 雷势并雷击 1 次。
38. U31：X=支付能量；X=0 不触发任何段、不触发 U02、不附雷；重演沿用已付 X；领域仍只附雷一次。

### 6.6 计数/快照/返能

39. "此前"（C20/U20/C26/U36/U40）读本次出牌开始时的快照，**不含本牌自身**这次雷伤。
40. U26 第 2 张实际攻击：力量/雷势在**支付后、牌效前**获得，影响该牌本次伤害；每实例独立、升级 2；两份 U26 各自触发。
41. U21：部署时本回合已 ≥2 次雷伤立即返 1，之后只在第 2/4/6… 次返；奇数不跨回合累计；每实例独立。
42. C26/U40 每次牌效独立返能，多张同名/同一张重复打出都各自结算（2026-10-28 无每回合限次）。
43. U36 无条件返能；抽牌条件看"此前"雷伤。
44. 雷甲 U34 每笔雷伤批次给一次格挡（不是每个敌人一次），+敏捷。

### 6.7 其他

45. 咬痕：完全格挡/致死命中都登记；同一次重演的后续命中读旧标记；不同敌人独立；跨回合持续本战。
46. 汲取只按雷伤实际生命损失回复（攻击部分不吸血）；完全格挡回 0。
47. 反雷：完全格挡也触发；敌人多段攻击每段各触发一次；不随领域延长；多次 C14 各自独立。
48. 留甲 U03：部署当回合不生效；从下回合起 `block -= min(N, block)`；重复获得取较低层；不触发敏捷/脆弱。
49. 坚甲 R02 只影响攻击伤害的格挡消耗；回合开始仍按默认清甲/留甲。
50. R05：额外获得当前格挡×2（合计 3 倍），该额外量不再计算敏捷/脆弱。
51. C19 保留跨回合；U10 强化等待可跨回合（不随回合结束清除）。
52. U12 本轮增幅覆盖随后敌方阶段（反雷在敌方阶段也吃增幅）。
53. 检索先占手牌位；雷法检索不包含"带雷伤的攻击牌"（B03 不是雷法）；回收 C15 允许雷法，R10 只回收攻击。
54. 手牌上限 10；"至多"选择从 0 开始；非"至多"按合法目标数执行。
55. 伤害预览必须与实际结算一致，随机目标不猜（R08 预览返回空）。

## 7. 需要用户裁决的问题

1. **【最高优先】领域"全压制"的边界**：是否接受 v1 只做"一次性事件 + 可枚举持续增益"两档（A+B），不碰敌人普通 AI/意图层？若要按用户表字面"禁用敌方全部特殊能力"，需要自研敌人行动层，工作量与风险会压过其余卡牌。
2. **迎战降级预案**：如果"玩家回合内驱动敌人 move"的原型失败（或多人不可用），接受哪种替代：①按意图拆解为等价命令（推荐）；②眩晕+提前行动；③本回合末行动、下回合跳过？还是必须实现原语义（则项目需要接受更高风险）？
3. **U03 留甲数值**：基础 6、升级 3（升级减少保留量=更强），卡面需要显示为"留甲 6／3"还是"保留 6／3 点格挡"？升级方向与直觉相反，确认不是笔误。
4. **R29 升级面**：用户表多出的"回收至多1张基础牌"确认删除？（定稿已删）
5. **2026-10-28 的四处机制修订**（U02 逐段、U21 每 2 次、C26/U40 不限次、U15 消耗为牌效）是否全部确认替代用户表旧规则？
6. **雷伤是否可格挡**：模拟器实现为"可格挡的非攻击伤害"，用户表关键词只写"雷电伤害，数值增加当前雷势"未明说；Mod 是否沿用"可格挡"？
7. **多人模式范围**：是否要求联机可用？迎战/领域压制/兽化在多人同步下复杂度显著上升，建议 v1 单人。
8. **美术仓数据更新**：`volibear_cards_repo/data/cards_source.json` 仍是 v4.1（39 张牌文字不同、关键词旧称"雷电成长"），卡面文案以定稿为准重导出，还是保持现状？
