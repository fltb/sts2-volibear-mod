## 1. 权威、独立预期与观测

玩法预期来自 [定稿契约](../reference/bear-forge/docs/volibear/DEVELOPMENT.md)、[178个牌面](../reference/bear-forge/docs/volibear/CARDS.md)及 [迎战结算契约](ENGAGE_SETTLEMENT.md)。bear-forge提供可移植的规则场景，不证明StS2敌人兼容。

测试使用独立期望记录：卡ID/升级、前置状态、动作序列、选择、期望事件顺序、期望数值/实体身份/牌区、规则出处。不得从被测C#的CanonicalVars、本地化替换值或本次实际结果反向生成期望；中文展示一致性单独检查。生成器可展开已有预期，不可从实现自动“猜答案”。

实际值取原引擎HP/格挡/能量/牌区/Power/History、实际支付/伤害结果、调度事件和必要的只读诊断。公共API不足时允许只读观测内部状态，但必须证明不改变控制流；“不读私有字段”不是质量保证。业务代码不得有测试通过分支；测试bootstrap只负责隔离、夹具和输入，不能另建结算器。

游戏记录证明发生了什么，不天然证明应该发生什么。雷伤批次/出牌身份等新增事件不能单独自证正确，须与独立预期、原引擎伤害和可见响应共同核对。Python门禁必须检查必需用例集合、证据完整性与实际数值，不只信passed字段。

## 3. 迎战 E 矩阵

数值夹具默认无力量/虚弱/易伤/减免/反击等额外影响；需要这些状态的行另设夹具。引擎动作期间HP、格挡与事件逐段记录；不能用最终格挡差当吸收。以下基准为机制夹具，不替代各张卡自身前置格挡与牌效顺序。

|---|---|---|
| E01 | 玩家80HP、5格挡，敌人普通攻击8 | 敌真实行动一次；吸收5、生命损失3、格挡0；完成一次 |
| E02 | 80HP、20格挡，敌攻8 | 吸收8、生命不变、格挡12；不是吸收0 |

| E06 | 本轮动作已消费；下一轮再迎战 | 当轮拒绝、下一轮依真实机会可执行，不跨轮误封锁 |
| E07 | 目标已死、失效、非本战实例 | 无行动/完成；不扣错另一敌人机会；不挂起 |

| E13 | 迎战召唤新敌人 | 按真实游戏召唤资格验证本轮机会；不得无来源强行设“新召唤物不行动”；R09当前目标集合与参考一致 |
| E14 | 后续敌方阶段及下一玩家回合 | 已消费敌人不重复动作；其他敌人不漏；意图/状态机推进恰好一次，生命周期触发不被整体跳过 |
| E15 | 嵌套伤害/另一敌人响应 | 仅计本窗口应归属的格挡吸收；内外窗口退出后归属恢复，不串战斗 |

| E17 | 不灭狂雷/万古不灭 | 每回合首次完成抽1/2；同回合第二次不抽，下一回合重置；拒绝/死亡不触发 |
| E18 | U04/U19/U32/R18，多份部署 | 按各自首次/每次规则，逐实例响应；完成响应在牌的迎战后续效果之前 |

## 6. 全敌人、状态机与 AI 的具体口径

### 6.1 建分母，不凭资产数量猜敌人数

锁定版本枚举ModelDb敌人/遭遇和真实状态机，再与程序集行为调查及本地化交叉检查。输出单次测试运行清单：enemy、encounter、state、move、transition(from/to/guard)、effect branch、Power/passive、fixture、领域策略、适用迎战路径。

旧研究的121类/356move/93遭遇仅是调查线索，不当本次实测分母；视觉资源数更不是怪物数。新发现项加入清单会扩大分母，不能为保100%删掉。反射枚举不能独自发现所有条件分支，须检查对应动作/状态转换/被动实现。

### 6.2 需要执行的矩阵

每个正式可达动作，以及受机制影响的被动/状态转换，至少覆盖：

1. 正常敌方调度，领域关；
2. 迎战提前执行，领域关；
3. 正常敌方调度，领域开；
4. 迎战提前执行，领域开。

确实不适用的单元给出原因；例如纯被动无独立move，但仍覆盖正常/迎战触发路径。不能用“枚举到”代替“执行且断言通过”。

每个状态转换须从合法前置状态触发，记录from、guard、实际move、副作用、to、下一意图及后续轮次。强制进入move可辅助单测，但不能算自然状态机转移覆盖。阈值用低于/等于/高于，计数用首次/临界/后续，随机分支用可控合法种子或测试随机输入覆盖每个已识别出口，不把一次随机运行当全分支。

特殊族必含：多段、非攻击、混合动作、召唤及召唤物机会、分裂/分段、复活、保护性阶段、偷牌/归还/逃跑、卡牌改写/削升级、限伤/无敌/不可选、反击、延迟效果、死亡清理和被动正负混合。每个已识别族落实实际StS2敌人夹具，不能只留标签空壳。

至少继续到提前行动后的敌方阶段及下一玩家回合；有更长记忆/周期的状态机继续到对应分支闭合。另对每个正式遭遇执行正常开战、动作推进与可完成终局验证，不只创建单个怪物。

### 6.3 三类对照

- 原生无Mod与加载Mod但不使用机制：匹配种子/合法夹具，比较可比的敌人行为、生命周期和随机消费；必要差异显式说明。
- 有领域与无领域：对允许效果要求一致，对被压制效果要求消失，对推进/必要清理要求仍正确。
- 迎战与正常调度：比较动作语义与下一状态，允许发生时点不同；不能要求全部时间戳/玩家回合触发机械相同。

### 6.4 不夸大的覆盖承诺

“全覆盖”限定为固定版本内已盘点的正式敌人、动作、可达状态转移、语义分支和相关被动清单100%通过；分别报告各项分子/分母，不能混成一个move百分比。

不声称穷举任意HP、牌序、随机数、多敌与无限跨回合组合，也不声称数学证明没有bug。卡牌×敌人×所有Power的笛卡尔积不冒充已执行；用上述全清单、机制定向组合、阈值、合法随机长序列补充。若用户要求完整笛卡尔积，须另定有限边界和执行预算，不偷换为抽样。

目前动态敌人清单与逐敌夹具尚未建立，这是W0/W6明确产出。本文是覆盖协议，不宣称已经列完全部AI分支。
