# 迎战结算架构决策与 POC 验收门

状态：待原型验证，非已实现。2026-10-31。此文覆盖旧方案中“API 全覆盖”和“意图拆解等价”的过强表述。

## 决策

保留现有迎战规则，不擅自降级。官方公开 API 尚未确认能直接在玩家出牌中驱动敌人行动；候选实现是自定义 EngageCmd/执行上下文，结合 Harmony 对内部动作执行入口和敌方调度器打补丁。PerformMove、MoveStateMachine 是调查线索，不是已验证的安全调用方案。必须针对 StS2 0.107.1 实际程序集核验签名、调用链和状态所有权。

不得从意图显示数值重建所谓“等价行动”：意图不是完整动作程序，不能覆盖隐藏状态、随机分支、阶段转换、附加状态、召唤等。眩晕也不天然等同于消耗本轮行动。任何语义降级必须由用户另行批准。

## 必须保持的结算契约

1. 卡牌先完成迎战前牌效，进入迎战窗口；后续牌效等待敌人真实动作完成。
2. 每敌每轮一次机会；已行动目标 performed=false、吸收=0，不触发迎战后响应。进入执行前预占资格，防止重入重复行动；异常路径需明确回滚/终止策略。
3. 执行目标当前真实动作，逐段经过原伤害、格挡、触发和死亡管线；不能仅模拟攻击数值。
4. 吸收为本次迎战中格挡实际吸收的伤害总量，不等于格挡净变化或消耗。坚甲不消耗格挡但照计吸收；完全格挡、多段攻击均计入。需核验 DamageResult 字段真实含义，不能假定字段存在。
5. 动作实际开始、玩家存活且战斗继续才算完成；仅完成时发布一次 engageCompleted，按规则执行遗物/能力响应，再继续后续牌效。死亡/战斗终止不继续打伤害。
6. 多目标迎战按稳定顺序串行；窗口分别记录目标吸收并按卡牌规则汇总，过滤死亡/失效目标，不以全局 block 前后差求吸收。
7. 正常敌方阶段跳过已提前结算的动作，但不可重复或漏掉状态机推进、回合计数、状态持续时间及应发生的回合触发。推进由迎战还是原调度器负责，必须根据实际调用链确定唯一所有者。
8. 隐藏行动状态以战斗/轮次/敌实例为身份，战斗结束清理，明确中途存档支持。瞬时吸收不入存档。窗口用 try/finally 退出，不遗留标记。
9. v1 优先单人验证；联机必须单独验证同步事件、选择上下文、随机数及执行顺序，不能据单人通过宣称联机支持。

## 原型顺序与验收

先核验内部调用链并写出实际方法签名/补丁点，再做一张测试卡与一个简单敌人，最后扩展以下用例：

| 用例 | 验收要求 |
|---|---|
| 单段攻击 | 玩家回合中真实执行，格挡/扣血正确，卡牌后续正确 |
| 多段攻击、完全格挡 | 吸收逐段累加，触发次数与原流程一致 |
| 攻击附带状态/混合行动 | 副作用、随机与敌自身状态不丢失 |
| 非攻击动作 | 按既定迎战资格与领域规则处理，不凭显示数字替代 |
| 同敌重复迎战/重入 | 同轮不重复，不触发虚假的完成事件 |
| 坚甲 | 格挡不扣但吸收计入，溢出正常扣血 |
| 反击导致敌死、玩家死、战斗结束 | 正确中断，无悬挂等待/残留窗口 |
| 多目标与中途死亡/召唤 | 顺序稳定，无错计或重复目标 |
| 后续敌方阶段与下一轮 | 不重复行动、不跳错下一招、回合计数与状态持续时间正确 |
| 完成响应 | 遗物、U04/U19/R18等按既定触发条件/次数结算 |
| 存档/恢复与特殊阶段敌人 | 明确支持范围及失败用例，不隐瞒例外 |

每例保存前后状态、事件顺序和日志。至少测试原调度无补丁对照，确认不迎战时原行为不变。只有原型通过才能把迎战改为“可实现已验证”。简单敌人的单次成功不代表全怪物兼容。
