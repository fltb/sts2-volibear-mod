# 89 张卡牌与角色动画的视觉触发映射

本文件与 `card_animation_bindings.json` 配套，把完整卡表逐一接到已交付的 **24 项主序列＋2 项领域变体，共26个可播放序列、940帧**。素材采样为 **24 fps**。这是便携的视觉事件约定，**不是某个游戏 SDK 已存在的 API，也不是另一套战斗规则**；接入者将宿主真实事件转换为这里描述的语义，再调用实际动画播放器。

卡牌规则、数值、目标选择、迎战、领域、兽化、格挡、伤害和胜负都由游戏权威逻辑决定。动画只消费已经确定的事实。clip 中名为 `impact`、`domain_on`、`feral_on`、`dead` 等标记只用于视觉/声音同步，不能因此执行伤害、生成手牌、增加状态或宣布死亡。

## 2. 一张牌最多一个主要角色动作

每次真实出牌以唯一 `play_id` 识别，主要角色 clip 最多启动一次。`play_id` 是本约定的语义名称，接入时可用引擎已有动作/队列/事务标识实现，不要求游戏存在同名字段。

- 单次攻击、群体攻击和多段攻击都只启动一套主体动作。每段真实命中允许一个短接触 VFX，目标和顺序来自游戏。
- 普通领域首次进入用 `domain_enter` 替换本卡原定主动作。C18/R31是明确的表现例外：真实进入后分别用 `domain_roar` / `domain_storm_leap` 作为唯一主动作，领域进入只用短VFX。不能再完整追加cast、attack、domain_enter。
- 兽化卡已经用 attack/block 出手时，后续只在手牌上显示转换；不再给角色追加 `feral_enter`。
- 真实敌方攻击的 `hurt`/`block`、死亡和领域自然退出属于独立战斗事实。它们可以打断当前出牌动作，不是为卡牌凭空追加一个效果。
- clip 内已烘焙的爪痕、雷波或火花可以承担主体特效。可选 VFX 不要叠成“又命中一次”的假象。

普通完成后重新读取当前状态选择 loop，不把动作起始时的状态缓存到结尾。优先级：死亡终帧保持 → 正在执行的有效动作/受击 → 领域弱姿态 → 领域待机 → 普通弱姿态 → 已确认的非战斗放松姿态 → 普通待机。弱姿态优先来自宿主已有表现条件；宿主没有时可读取动画manifest.state_rules明确的视觉滞回阈值（进入0.30、退出0.35）。这只切换姿态，不增加弱化/负面状态，也不改变游戏数值。

## 3. 便携语义事件

这些键只是 JSON 映射的接口语义。宿主可能使用事件总线、队列动作、状态差量或其他真实接口；接入者据实际代码对接，不能假定有 `OnCardBeastify()` 等现成方法。

| 事件键 | 仅在什么事实成立时使用 | 不能做什么 |
|---|---|---|
| `on_play` | 一张卡实际被打出，获得本次唯一事务/动作标识 | 不凭点击预览就播放成功；不重算牌效 |
| `after_block_gain` | 本卡或所属能力引起格挡真实正变化；R05读乘3后的实际变化 | 不在动画中乘格挡、加敏捷或计算脆弱；零增量不假示收益 |
| `before_forced_enemy_action` | 游戏确认本卡的一次迎战敌行动确实将开始 | 不由此调用敌方行动；已用过行动的敌人不补演 |
| `after_forced_enemy_action` | 本次真实行动/动作组已结算，可关联其发起卡与结果 | 不把普通敌方回合或未发生的迎战当成成功反扑 |
| `on_damage_hit` | 本卡直接效果或明确归属本卡能力的一段真实伤害已处理 | 不根据动画帧、闪电分叉或目标特效数量增加伤害 |
| `on_domain_changed` | 所属角色的领域 active/时长/永久属性真实改变 | clip的domain_on/off标记不授予或清除领域 |
| `on_card_beastify` | 一个具体手牌实体实际成功转成爪形或躯形 | 不变换角色游戏状态；已有形态保持不算又成功转换 |

不是每张卡都注册全部事件。JSON 只在该卡真实存在相应牌效时列出钩子，例如 T02 虽叫“风暴之躯”，并不提供领域；T01/T02 是已经产生的形态，打出它们也不再次触发手牌兽化。

对于抽牌、检索、回收、消耗、能量、力量、敏捷、治疗、减费等短 VFX，直接绑定宿主对应的实际效果回执。映射中写明触发条件，但不虚构另一组引擎方法名。没有发生的分支不展示成功反馈。

## 4. 七张主动迎战：顺序必须一致

| ID | 正确游戏效果次序 | 主体 clip | 迎战后如何表现 |
|---|---|---|
| B04 挺身迎战 | 获得格挡→普通攻击→迎战 | `attack` | 结束接招，回当前状态；无额外counter |
| C04 擂首一击 | 普通攻击→施加虚弱→迎战 | `attack_heavy` | 结束接招，回当前状态；无额外counter |
| C10 以牙还牙 | 获得格挡→迎战→造成8＋吸收的伤害（升级12＋吸收） | `counter` | 真实迎战已发生且后置效果成立后播counter反击段 |
| C11 正面迎敌 | 获得格挡→迎战 | `block` | 结束接招，回当前状态；无额外counter |
| U28 雷霆反扑 | 获得格挡→迎战→全体造成4＋吸收的雷伤（升级6＋吸收） | `counter` | 真实迎战已发生且后置效果成立后播counter反击段 |
| U35 霹天雳地 | 获得格挡→全体雷伤→迎战 | `cast` | 结束接招，回当前状态；无额外counter |
| R09 众敌皆来 | 获得格挡→全体迎战→全体造成等同吸收的雷伤 | `counter` | 真实迎战已发生且后置效果成立后播counter反击段 |

**B04、C04 的攻击在迎战前；U35 的雷伤也在迎战前。** 它们不能套用“先挨打再统一反击”的模板。C11 只有格挡和迎战，没有后置伤害。只有 C10、U28、R09 使用后置反击段。

### 后置反击的必要条件

同时满足：本次迎战至少有一个敌行动实际开始；本次行动（R09为整个动作组）已经结算；角色仍活着；战斗继续；对应的后置反击效果实际进入视觉呈现。没有真实迎战时，不播放“先承伤再反扑”的成功表演。若游戏仍然结算了某项后置伤害，按真实结果显示普通命中 VFX，不谎称发生过迎战。

R09 只在所有实际开始的敌行动处理结束后播一次群体反雷。不要每个敌人行动后各反雷一次；不能把无剩余行动的敌人补进动画队列。多人战斗中保留真实攻击目标：只有实际受击者播放 hurt/block，发起迎战者不自动假演受伤。

### 使用已有 counter 的反击段

现有 `counter` 为32帧：`guard_on` 在0.35秒，`absorbed_impact` 在0.52秒，`counter_impact` 在0.84秒，`recover` 在1.08秒。普通皮肤真实迎战结束后从 **第14帧（0基，约0.583秒）播放到第31帧**，跳过已经发生的前半段架挡/吸收；不要在敌人打完后再完整演一次“尚未受击”的准备过程。可用播放器已有的起始帧/子片段能力接入；若宿主不支持，离线派生这一帧段作为视觉适配，不改伤害逻辑，也不假称另有未交付的独立clip。领域内没有专属domain_counter，回退到现有 **domain_attack完整第0—23帧**；禁止套用普通counter的32帧范围。普通counter的视觉事件时间要减去14/24秒，片段起点之前的guard_on/absorbed_impact跳过；领域回退仍用domain_attack原始事件时间。

包内 `animations/integration/VolibearSpriteFrames.cs` 已提供可选适配函数 `PlayPostChallengeCounter(sprite, machine, flags)`。它先请求并确认实际状态，再对普通counter定位第14帧；领域回退保持domain_attack第0帧。返回实际Clip、起止帧与TimeOffsetSeconds，拒绝时返回null。C10/U28/R09使用这一函数，不能仅直接SetTrigger Counter，否则普通皮肤会从完整32帧起点重演承击。该方法是本包提供的适配代码，不是虚构的游戏内建方法。

视觉事件桥接读取返回的实际Clip：普通counter的counter_impact源时间0.84秒，减14/24秒后约0.2567秒；领域domain_attack使用自己的impact（0.54秒），偏移为0。不要将counter_impact名称或0.84秒时刻套入领域fallback；片段起点之前的事件跳过。任何事件都不再施加伤害或其他规则。

若角色死亡，立即停止当前片段并清空排队的后置 counter。不能让死亡后残留的动画回调再次打出雷伤、抽牌或恢复 loop。

## 5. 领域进入、续时、退出与现有领域动作

领域监听放在全局角色表现路由，按角色和真实状态修订去重；卡牌表只描述由哪张卡触发，不再各自重复执行一次进入动画。

| 权威状态变化 | 表现 |
|---|---|
| false → true | 常规用domain_enter一次；C18/R31分别以domain_roar/domain_storm_leap加短进入VFX替代完整enter。结束按真实状态回domain loop |
| true → true，仅续时/永久化等 | 一个短domain_pulse，不重播enter；卡本身仍可用已有领域版常规动作 |
| true → false，角色存活 | `domain_exit` 一次，结束按真实normal/weak状态选loop |
| 领域中死亡 | `domain_die`优先，跳过独立exit；死亡保持终帧 |
| enter被新动作/实际受击打断 | 不因没播完而再次enter；领域存在仍读权威状态 |

本表12张可能直接建立领域的卡：C05、C14、C18、C21、U19、U32、U37、U39、R01、R13、R25、R31。U19以后触发的续时也只发pulse。R13在已有领域时是治疗分支，不伪装成续时；R01的永久领域由游戏既有状态保持，不能因为动画结束就解除。

为了保持一张卡一个主要动作，可能首次开域且当前尚无领域的卡在on_play先保留动作额度，等待实际false→true；此时普通卡用domain_enter替换原定clip；C18选择domain_roar，R31选择domain_storm_leap，同时只发一次短进入VFX并将本次进入表现标记为已处理。U37先雷伤再领域，前面的真实雷伤用短VFX表现，不能把规则顺序倒置成先开域。若实际转换没有发生，也不能凭卡名播放成功进入。

| 原动作 | 已有领域时选择 |
|---|---|
| attack | domain_attack |
| cast | domain_cast |
| hurt | domain_hurt |
| block | domain_block |
| weak_loop | domain_weak_loop |
| die | domain_die |
| attack_heavy | domain_attack，辅以重击接触/地面短VFX；没有domain_attack_heavy |
| roar | domain_roar；C18实际授予领域后使用此版，U23按当前领域状态选择 |
| storm_leap | domain_storm_leap；R31在本卡真实领域状态建立后使用此版 |
| bite、counter | 回退到domain_attack完整动作，保留咬击/反击的实际效果VFX；不假称有专属领域变体 |
| feral_enter | 回退到domain_cast完整动作，以保持领域皮肤；不创建变身状态 |

### 咆哮与跃击的实际标记

roar/domain_roar为36帧、1.5秒：0.52秒roar_release，0.98秒roar_peak，1.25秒recover。storm_leap/domain_storm_leap为48帧、2秒：0.46秒takeoff，0.92秒apex，1.44秒landing_impact，1.63秒aftershock，1.8秒recover。这些标记只安排姿态、声浪和落地特效；R31的移除格挡、普通伤害、对其他敌人的雷伤仍按游戏真实顺序处理，不由landing_impact重新执行。

## 6. 兽化作用于手牌，不给角色添加永久形态

真正转换手牌的卡是 U41、U42、U43、R27、R28、R29、R30。只在游戏报告某个材料实体成功转换后显示该牌由原图变成爪形/躯形的短过渡。升级、保留、减费、消耗与战后恢复仍由游戏处理。

- U41 已用 attack，U42 已用 block：后续只做手牌转换VFX，不再追加feral_enter。
- U43、R27、R29，以及R28/R30本次入场转换，可在本次首次真实成功转换后播一套feral_enter。一个批次不论转几张，角色最多enter一次。已有领域时用domain_cast作为短时表演回退，避免闪回普通皮肤。
- R27选0、R28选0、R29没有成功转换目标等情况，不播放“转换成功”的主体表演。
- R28/R30以后回合的被动转换只做手牌VFX，不重播完整入场动作。
- feral_idle只是可选短时凶猛姿态，最多12帧（0.5秒）；仅在没有领域、弱姿态或其他动作需要表现时使用，新动作立即打断。它不构成永久变身buff。
- R12的本能释放可用feral_enter作短时表演，不意味着它额外转换手牌。U23现在使用专用roar/domain_roar，不借用兽化姿态。
- T01/T02打出后按真实规则消耗；不因使用它们而让角色进入永久feral_idle。

## 7. 伤害、格挡、死亡和重演

实际攻击完全被格挡时可以显示护边接触，但不能显示受到生命伤害的反馈。确有生命损失时播放hurt/domain_hurt；同一段同时吸收格挡和扣生命，用受伤主体动作加短护边即可，避免先完整block再完整hurt。连续多段来击保留短冲击感，不把每段都排成一秒的长队。

死亡优先级最高，根据死亡前实际领域状态选择die/domain_die，清空待播的出牌动作、counter、feral和loop请求。死亡动画内部标记不再次执行死亡逻辑；游戏如果真实复活，再按当前实际状态恢复对应待机，不凭clip推定复活或恢复旧领域。

多段、随机段、X段与重演都用游戏已经确定的结果：C02/T01两段、U06三段、R23三次同目标雷、R08四次真实随机目标、U31实际支付X次。身体主clip一次；每段只接短VFX。U11的重演属于额外结算牌效，不重新算一次实际出牌动画预算；不要在表现层触发成长或复制牌效。
